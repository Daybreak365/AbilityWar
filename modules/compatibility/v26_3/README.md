# Minecraft 26.3

기존 Common / Compatibility 인터페이스를 구현하는 26.3 전용 모듈입니다. CraftBukkit 26.3의 버전 없는 패키지와 공식 NMS 이름을 사용합니다. 과거 버전용 SpecialSource 재매핑을 이 모듈에 적용하지 않습니다.

## 빌드

- Maven 실행: JDK 21 (기존 Kotlin 1.5.20 컴파일러 사용)
- 26.3 서버 및 이 모듈 컴파일: JDK 25
- 공식 BuildTools: `java -jar BuildTools.jar --rev 26.3 --compile CRAFTBUKKIT`
- BuildTools와 프로젝트가 같은 로컬 Maven 저장소를 사용해야 합니다.

JDK 25를 `~/.m2/toolchains.xml`에 등록합니다. 경로는 실제 설치 위치로 바꿉니다.

```xml
<toolchains>
  <toolchain>
    <type>jdk</type>
    <provides><version>25</version></provides>
    <configuration><jdkHome>/path/to/jdk-25</jdkHome></configuration>
  </toolchain>
</toolchains>
```

저장소 루트에서 실행합니다. 다른 toolchains 파일은 `-t /path/to/toolchains.xml`로 지정할 수 있습니다.

```sh
mvn -P minecraft-26.3 -Dgpg.skip=true clean verify
```

출력: `modules/Jar/target/AbilityWar-26.0.1-mc26.3.jar`. 이 프로필의 JAR은 **26.3 전용 개발 검사용**입니다. 배포용 통합 파일은 프로필 없이 `mvn -Dgpg.skip=true clean verify`로 빌드하는 `AbilityWar-26.0.1.jar`이며, 기존 버전별 모듈과 26.3을 모두 포함합니다. 각 버전의 CraftBukkit 의존성이 필요하며, [변경되지 않은 공식 호환 모듈 재사용](../../../tools/README.md)도 지원합니다. 기존 모듈의 Java 8 바이트코드 대상은 유지됩니다.

26.3 감지는 `Bukkit.getBukkitVersion()`을 사용합니다. CraftBukkit의 `26.3-R0.1-SNAPSHOT`, Paper의 `26.3.build.<번호>-<채널>` 및 `26.3.local-SNAPSHOT` 형식을 인식합니다. 다른 26.x 릴리스나 프리릴리스는 자동으로 지원 버전으로 취급하지 않습니다.

## 검증

`Compatibility/test`의 JUnit 검사는 기존 버전 감지, 26.3 감지, 미지원 버전 거부, 버전 비교를 검증합니다. `Jar/test`의 검사는 최종 배포 JAR을 별도 클래스 로더로 열어 Paper 26.3-222 버전 및 서버 종류 판별을 확인하고, 버전 클래스가 현재 컴파일 결과와 일치하는지 검사합니다. 위 `verify` 명령에 모두 포함됩니다. `-Dgpg.skip=true`는 개인 서명 키가 없는 로컬 검증에서 배포 서명 단계만 생략합니다.

Shade가 JAR을 덮어쓰므로 Maven JAR 플러그인의 `forceCreation`을 활성화했습니다. `clean` 없이 재빌드해도 이전 JAR에 포함된 의존성 클래스가 남지 않도록 합니다.

추가 서버 검사는 `integration-test`에 있는 별도 테스트 플러그인으로 실행합니다. **테스트용 월드에서만 실행하세요.** 엔티티와 블록을 만들고 검사가 끝나면 서버를 종료합니다. 배포 JAR에는 포함되지 않습니다.

1. 별도 디렉토리에 CraftBukkit 26.3 서버를 준비하고 한 번 실행해 `bundler/`를 생성합니다. 서버 이용 약관을 확인하고 테스트 서버를 종료합니다.
2. 저장소 루트에서 `JAVA_HOME=/path/to/jdk-25 bash modules/compatibility/v26_3/integration-test/build.sh /path/to/test-server`를 실행합니다. 기본값은 통합 JAR입니다. 26.3 전용 파일을 검사하려면 두 번째 인수로 `modules/Jar/target/AbilityWar-26.0.1-mc26.3.jar`를 지정합니다.
3. 검사 대상 CraftBukkit 또는 Paper 서버를 별도 테스트 디렉토리에 준비합니다. 배포 JAR과 생성된 `modules/compatibility/v26_3/target/integration-test/CompatibilitySmoke.jar`를 테스트 서버의 `plugins/`에 복사합니다.
4. Java 25로 서버를 시작합니다. 로그에서 `SMOKE RESULT`의 `failed=0`과 각 `PASS`를 확인합니다. 서버 종료 코드 0만으로 성공을 판정하지 않습니다.

검사 대상: 서버 종류 판별, 사운드와 변경된 파티클 이름, 커스텀 머리, 홀로그램 생성·수정·이동·제거, 월드보더, 블록 레이 트레이스, 흡수 체력·엔티티 조작, 피해 종류, 화살 상태, 더미 생명주기, 낚싯줄 제거, 은신 능력 등록, 은신 패킷의 원본 보존과 자기 장비 유지.

온라인 클라이언트 두 명으로 은신/해제, 재접속, 차원 이동, 낚싯줄 표시, 더미 스킨·DPS 표시를 추가로 확인할 수 있습니다. 자동 서버 검사는 클라이언트 렌더링까지 검증하지 않습니다. 외부 스킨 서비스가 차단된 환경에서는 이름 기반 머리의 스킨 조회가 실패할 수 있습니다.

검증 기록: Java 25, CraftBukkit `4663-Bukkit-c4db4c3` (26.3)에서 서버 검사 14개와 `/abilitywar` 명령 응답, 정상 종료를 확인했습니다. Paper `26.3-222`에서 `(PAPER v26_3)` 활성화, 서버 검사 15개 통과와 정상 종료를 확인했습니다. Maven `verify`에서 버전 단위 테스트 6개와 최종 배포 JAR 검사 3개를 통과했습니다. 기존 버전을 포함한 기본 Maven 구성 검증은 통과했으며, 모든 과거 서버의 재빌드·실행은 이번 검증 범위에 포함되지 않습니다.

## 공포·마그넷 수정 및 카니스 원복 검증

추가 게임플레이 검사는 테스트 서버 시작 옵션에 `-Dabilitywar.gameplaySmoke=true`를 넣어 실행합니다. 기존 기반 기능 검사에 이어 별도 게임과 서버 플레이어 엔티티를 만들어 약 24초 동안 실행합니다. 테스트 플레이어의 서버 틱을 직접 진행하며 실제 클라이언트 화면을 검증하지는 않습니다. 전용 테스트 월드에서만 사용하세요.

- 공포: 2틱짜리 실명의 반복 적용 대신 지속되는 실명을 적용합니다. 공포 연장·중단과 별도로 받은 강한 실명의 보존을 검사합니다.
- 마그넷: 마커 아머스탠드의 물리 이동 대신 직접 궤적을 계산합니다. 발사 후 이동, 벽 충돌, 투사체 유인, 능력 제거 시 정리를 검사합니다.
- 카니스: 리메이크 이전 원본으로 복원했습니다. 철괴 우클릭으로 바로 탑승하고, 탑승 중 기력을 충전하여 철괴 좌클릭으로 쾌속 질주합니다. 질주가 끝나도 탑승을 유지하며 기존 랜스 충전과 하마 시 흡수 체력·재소환 대기시간을 사용합니다.

리메이크의 자동 하마, 검 좌클릭 돌진, 새 연출 및 전용 이동 API는 제거했습니다. `charge-seconds`, `dash-seconds`는 원본 카니스에서 사용하지 않습니다.

검증 결과: Paper `26.3-222`, Java 25에서 기반 기능 및 게임플레이 검사 **30개 통과, 실패 0개**. Maven 단위 테스트 6개와 최종 배포 JAR 검사 3개도 통과했습니다. 카니스 클래스 10개는 리메이크 전 `paperfix2`와 바이트 단위로 일치하며, 공포·마그넷 클래스는 `gameplay1`과 일치합니다. 카니스 흡수 체력은 원본 역순 타이머의 동작 그대로 42에서 2로 감소하는 것을 확인했습니다.

## 내부 안정성 및 처리 비용 개선

능력의 수치, 조작, 탐색 범위와 순서, 파티클 수 및 액션바 전송 주기를 유지하면서 다음 공통 처리를 정리했습니다.

- 능력·게임 설정을 저장한 뒤 수정 시각을 기록하여, 값 조회가 방금 저장한 YAML을 다시 읽고 쓰지 않도록 했습니다. 외부 파일 변경 감지와 미저장 설정값의 우선순위는 유지합니다.
- 능력을 제거할 때 하위 이벤트 구독도 해제하고, 이벤트 콜백 예외 후에도 대기 중인 등록·해제를 처리합니다.
- 내부 타이머 컬렉션은 중단된 반복자가 변경을 막지 않는 스냅샷 순회를 사용합니다. 콜백 중 변경을 지연해야 하는 내부 경로는 `forEach`로 관리하여 종료 시 FIFO 순서로 반영합니다. 애드온이 직접 사용하는 기존 `QueueOnIterateHashSet`의 일반 반복자는 순회 종료까지 변경을 지연하는 기존 규칙을 유지합니다.
- 네 가지 능력 GUI는 기존 임시 아이템을 표시한 뒤 다음 서버 틱에서 설명을 완성합니다. 설정과 애드온 필드, Bukkit 인벤토리를 메인 스레드에서 접근하고, 페이지 변경·닫기·퇴장 후 오래된 작업을 폐기합니다.
- 엔티티 수집의 누적 배열 복사를 제거하고, 홀로그램 갱신 패킷과 액션바의 동일한 조합 문자열을 재사용합니다. 액션바 표시 시간 갱신과 주기적 재전송은 유지합니다.
- 내장 능력 목록을 한 곳에서 관리하되 전체 등록 91개와 선택 목록 79개의 기존 순서, 버전 분기, 베타·만우절 필터를 유지합니다.
- `Plugin`이 공통 코드와 외부 라이브러리의 기존 패키지 재배치를 담당하고, 최종 `Jar`는 이 결과와 버전별 어댑터만 합칩니다. 애드온용 `Plugin` 아티팩트의 클래스 경로는 유지합니다.

`Plugin/test`는 설정 재조회·외부 수정, 이벤트 정리, 반복 중 변경과 예외, GUI 작업 폐기, 탐색 순서·경계, 능력 등록 목록을 검증합니다. `Jar/test`는 최종 배포본의 버전 판별에 더해 Plugin·26.3 어댑터 클래스 보존과 중복 ZIP 항목 여부를 검사합니다. `verify`에 포함되며 `clean` 없는 재빌드도 검사할 수 있습니다.

게임플레이 서버 검사에는 두 관전자 홀로그램 갱신 경로, GUI 페이지·정렬 변경과 닫기, 중단된 타이머 순회 후 등록, 능력 제거 시 타이머·하위 이벤트 정리, 액션바 시간 갱신·만료 검사가 추가되었습니다. 실제 클라이언트 렌더링이나 다인전 성능 개선 폭은 이 검사로 측정하지 않습니다.

최종 검증: Maven `clean verify` **47개 통과**(버전 단위 6개, 공통 코드 단위 36개, 최종 JAR 검사 5개), Paper `26.3-222` **43개 통과·실패 0개**, 정상 종료를 확인했습니다. 기존 버전을 포함하는 기본 프로필의 Maven `validate`도 통과했습니다. 카니스 10개·마그넷 3개·공포 1개 클래스는 `gameplay2`와 바이트 단위로 동일합니다.
